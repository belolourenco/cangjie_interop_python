# Cangjie Python interop

This library implements `std.core.ForeignRuntime<PythonRuntime>` on top of embedded CPython. Use `Extern<PythonRuntime>` for Python values, with Cangjie syntax for calls, members, and indexing.

> **Disclaimer:** This project was generated by AI and is provided without any guarantees of correctness.

```cangjie
import interop_python.PythonRuntime

main() {
    let math = PythonRuntime.getModule("math")
    let input: Extern<PythonRuntime> = 81
    let result = PythonRuntime.fromExtern<Float64>(math.sqrt(input))
    println(result)
}
```

Cangjie can implicitly convert supported values to `Extern<PythonRuntime>` where that type is expected. Use `PythonRuntime.fromExtern<R>` to convert a Python value back to Cangjie.

## Requirements

- Cangjie SDK with compiler support for `Extern<T>` and the `std.core.ForeignRuntime<T>` interface.
- `clang`, `ar`, `ranlib`, and `make`.
- Python development headers and embed linker flags available through `python3-config`.

Source the SDK's `envsetup.sh` before building, using the path to your installation.

```sh
source $CANGJIE_HOME/envsetup.sh
```

Check Python discovery with:

```sh
python3-config --includes
python3-config --ldflags --embed
```

## Build

From the repository root:

```sh
make build
```

`make native` builds `build/native/libpython_bridge.a` from `native/bridge/python_bridge.c`.

## Test

Run the full suite with:

```sh
make test
```

The test packages link against `libpython_bridge` and the CPython embed library discovered by `python3-config`. To select another Python installation, pass its configuration command to Make, for example `make test PYTHON_CONFIG=python3.14-config`.

## Runtime Notes

- CPython is initialized once per process and stays available for the life of the process. The bridge acquires the GIL before touching Python objects.
- Returned `Extern<PythonRuntime>` values own strong Python references until the Cangjie wrapper is destroyed.
- The bridge uses Python item access for indexing and requires nonnegative integer positions for built-in lists and tuples. For built-in dictionaries, member lookup checks Python attributes first and then string keys.
- Interop failures use the corresponding `std.core` exception type. `ForeignRuntimeException` includes the Python traceback when CPython supplies one. A call-time `TypeError` without Python frames is treated as an argument error.
- File-based module imports execute the file again for each `PythonRuntime.getModule(path)` call.
